LightNet allows search engines, such as Google, to index your site by default.
You can ask them to exclude your whole site or individual pages from search results.

## Hide from search engines

Set `disallowSearchIndexing` to `true` to ask search engines not to index your site or a page.
LightNet adds this robots meta tag to the `<head>` of the affected HTML pages:

```html
<meta name="robots" content="noindex">
```

See also [Block Search Indexing with `noindex`](https://developers.google.com/search/docs/crawling-indexing/block-indexing) in Google Search Central.

<Aside type="caution" title="Noindex does not restrict access">
Pages remain accessible to anyone who has the link.
Search engines and other bots are not forced to respect `noindex` directives or `robots.txt` files.
</Aside>

### Hide the whole site

Set `disallowSearchIndexing` to `true` in your LightNet configuration:

```js title="astro.config.mjs" ins={7}
import lightnet from "lightnet";
import { defineConfig } from "astro/config";

export default defineConfig({
  integrations: [
    lightnet({
      disallowSearchIndexing: true,
      // ...
    }),
  ],
});
```

This applies `noindex` to all generated HTML pages unless a page overrides the setting.

### Hide an individual page

For a [Markdown page](/build/pages/markdown-page/), set `disallowSearchIndexing` in the frontmatter:

```md title="src/pages/en/about.md" ins={3}
---
layout: "lightnet/layouts/MarkdownPage.astro"
disallowSearchIndexing: true
---

# About

About this site.
```

For a page built with the [`Page`](/build/pages/fundamentals/) component, pass `disallowSearchIndexing` directly:

```astro ins={5}
---
import { Page } from "lightnet/components";
---

<Page disallowSearchIndexing>
  <h1>Public page</h1>
</Page>
```

The page-level value takes precedence over the site configuration.
To allow indexing for a page when the whole site uses `noindex`, use `disallowSearchIndexing: false` in its frontmatter or `<Page disallowSearchIndexing={false}>` in its component.

LightNet does not support requesting `noindex` for individual [media items](/content/media-items/).

### Remove blocking `robots.txt` rules

If your existing LightNet project still uses `robots.txt`, remove the file and use `disallowSearchIndexing` instead.

A `robots.txt` rule like `Disallow: /` blocks search engines from crawling your site.
If a search engine cannot crawl generated HTML, it cannot see the `noindex` directive.
As a result, the page may still appear in search results if the search engine already knows about it from before or finds links to it elsewhere.

See also [Understand the limitations of a `robots.txt` file](https://developers.google.com/search/docs/crawling-indexing/robots/intro#understand-the-limitations-of-a-robots.txt-file) in Google Search Central.

### Hide other files

To ask search engines not to index files such as PDFs, add an `X-Robots-Tag: noindex` HTTP response header to the files.
The `disallowSearchIndexing` setting affects generated HTML pages; it does not add this header to other files served through your site.

If the domain or subdomain serving your files is proxied through Cloudflare, you can add the header using a **Response Header Transform Rule**.
For example, to apply `noindex` to PDF files:

<Steps>

1. Open the **Cloudflare dashboard** and select the **domain** serving your files.
2. Go to **Rules > Overview > Create rule > Response Header Transform Rule**.
3. Enter a descriptive rule name, such as "Do not index PDFs".
4. Under When incoming requests match, select Custom filter expression and configure:

   | Field | Operator | Value |
   | --- | --- | --- |
   | URI Path (`http.request.uri.path`) | ends with | `.pdf` |

5. Under Modify response header, configure:

   | Operation | Header name | Value |
   | --- | --- | --- |
   | Set static | `X-Robots-Tag` | `noindex` |

6. Select Deploy to activate the rule.
7. Open your browser's developer tools and select the Network tab. Open or reload a PDF URL from your site, select the PDF request, and inspect its response headers. You should see `X-Robots-Tag: noindex`.

</Steps>

This rule matches URL paths ending in lowercase `.pdf`. Adjust the condition if your files use other extensions or paths.
Search engines must be allowed to crawl the files to discover the header, so do not block those URLs in `robots.txt`.

See Cloudflare's [response header transform rule instructions](https://developers.cloudflare.com/rules/transform/response-header-modification/create-dashboard/) and Google's [documentation for the `X-Robots-Tag` header](https://developers.google.com/search/docs/crawling-indexing/robots-meta-tag#xrobotstag).

## Improve search engine performance

LightNet automatically generates sitemaps and `robots.txt` for your site.
These files help search engines discover and crawl your content:

- A sitemap lists page URLs, helping search engines find pages without relying only on links from other pages or sites. This is especially useful for a large media library or newly added content.
- A `robots.txt` file provides instructions about which parts of the site search engines can crawl. It can also tell search engines where to find a sitemap.

LightNet generates these files for you, so you do not need to maintain them by hand.
For more background, see Google's [sitemap overview](https://developers.google.com/search/docs/crawling-indexing/sitemaps/overview) and [introduction to robots.txt](https://developers.google.com/search/docs/crawling-indexing/robots/intro).

To benefit from this discovery, allow search engines to crawl and index the pages you want people to find.
LightNet allows indexing by default, so leave `disallowSearchIndexing` unset or set it to `false` for those pages.
Sitemaps and crawling instructions help search engines find your content, but do not guarantee inclusion in search results or a particular ranking.
